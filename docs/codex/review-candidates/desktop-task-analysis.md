# Desktop task analysis (police-report forms): restricted candidate (not approved)

**Status:** outline only, 23 November 2026. **Not drafted for publication and not in the public release.** The owner's review notes describe this as a distinct, task-level case. It differs from the system-level Claims case.

**Candidate route:** `/investigations/desktop-task-analysis/` (provisional). **Stable ID:** assign when a private draft exists.

## What the owner has reported so far

- Manual desktop interaction analysis of a repetitive police-report form task: screen capture and step documentation.
- An alternative process using an existing internal auto-text capability, so no new software was needed.
- I demonstrated the original and revised approaches to the team and supported its implementation.
- A reported result of about 88% less form-completion time. This is **unverified** and must not appear publicly until its measurement basis is reviewed.

## Evidence needed before drafting public wording

| Question | Why |
| --- | --- |
| Original and revised task durations, how they were timed, and with whom | An 88% figure needs its unit, baseline, method and sample. |
| Screen-recording and step-documentation method | This is the case's distinct capability; reconstruct it without confidential screens. |
| Implementation date or duration, and evidence of team adoption | Separates *demonstrated* from *adopted*. |
| Was a software purchase actually being considered? | If not, say “required no additional purchase”, never “prevented a procurement”. |
| What can be shown publicly | A stylized task replay only; no real system screens, field names or invented click counts. |
