# Adding investigations and explained relationships

Use existing private authoring storage and the versioned content model. No new CMS is introduced. Local studio saving/review/preview remains distinct from hosted publishing, which is not implemented. New narrative fields are schema/template support; the studio has no dedicated form for every field yet. Do not claim universal copy editing.

1. Create a restricted draft with a stable UUID, revision, editable slug, original manuscript and separate proposed edits. Preserve source passages and individual review decisions. Save incomplete narrative fields; do not invent dates or evidence to complete a template.
2. Optionally add `investigation` (schemaVersion1). Select `boundary`, `comparison`, `network` or `revision`. Provide visual.left/right/explanation. Geometry is conceptual, not an operational measurement. Labels, caption and prose convey the meaning without SVG or motion.
3. Add whichever narrative fields suit the account: observedCondition, workingExplanation, investigation, relationshipDiscovered, response, consequence, limitations. Selected narratives require observed condition, investigation, relationship and limitations. The template omits absent fields. Existing case/essay/field-note/poetry records remain valid without narrative metadata; poetry must remain verse, not an investigation layout.
4. Add statements with immutable UUIDs, exact wording, kind, contribution level, evidenceIds and a limitation. Classifications are enumerated in `src/content/investigation.ts`. Keep intended benefits distinct from observed adoption and measured impact. Measured results require selected metric evidence with unit, denominator, period, baseline and method. Missing provenance is a review blocker, not an invitation to fabricate it.
5. Evidence and assets retain their own IDs, rights, visibility and review records. Keep employer originals/internal locators private. Only owner-supplied rights-cleared derivatives may reach a future release. Every selected statement source must be approved public evidence; draft-only/unverified statements cannot enter a selected narrative.
6. Add canonical `relationships` with stable IDs, typed endpoints, directional meaning, rationale, supporting evidence and proposed status. Connections automatically supply backlinks and page-specific linked metadata only when selected. Do not infer supported principles from tags. `src/content/connections.ts` contains homepage editorial comparisons, explicitly interpretations, separate from approved canonical edges.
7. Reserve aliases before changing a slug. Preserve legacy content IDs and existing fragments in the migration ledger. Telematics is a review-only candidate, not a replacement for the claims knowledge reference. An arbitrary proposed route must continue to404 until selected and built.
8. Run the six existing passes. Exact-candidate approval must bind application/content revisions, source/asset selections and digests through authenticated authority. Schema checks and an approvedBy string do not authenticate approval. A new draft can coexist with the selected earlier revision.
9. After owner approval and a separately authorized release, use the trusted public projection to generate pages, collection metadata, backlinks/search/graph/sitemap. No release loader for new production manuscripts exists today; `content/public-release.json` remains empty. Do not hand-edit it to bypass approval.

## Recovery

No storage migration or release occurred. Revert runtime/schema commits in reverse order on the review branch, preserving the audit/history. Optional fields require no migration of older records. Preserve any newly saved drafts on export before rolling code back to a validator that predates these fields; older strict schemas reject them. Rebuild output after rollback. Existing approved/public content and unrelated authoring worktrees are unaffected. Never roll back publication state by marking drafts approved.
